## 0. 结论摘要

1. **方案整体可行**。把 AI 的产出收敛为 `EditIR`、把编辑决策与媒体执行分层，
   是这套系统最关键且正确的架构决定。
2. **P0 闭环与 Orchestrator 已落地**：导入 → ffprobe → EditIR →
   编译 cut/concat → ffmpeg 执行 → ffprobe 断言；
   Orchestrator 动态建图、并行调度子智能体、最终决策智能体输出答案。
3. **每任务工作区已强制实施**：用户文件先复制进
   `workspace/projects/{project_id}/`，后续只操作副本；测试校验源文件哈希不变。
4. **P1 感知与包装已落地**：OpenCV/PySceneDetect 镜头切分、质量标记、
   人脸锚点、contact sheet；9:16 重构图、SRT/VTT + 可选烧录、-14 LUFS 响度归一。
5. **Phase 1–4 增强已落地**：分块转写、章节、取消/续跑、内容寻址缓存；
   候选片段 + FTS5、Critic、Segment 缓存/并行 cut、IR diff；
   两阶段大纲、硬件编码回退、proxy-first、VLM 视觉摘要、JSON policy；
   以及 source_hash 持久化、并行项目 bundle、单次后处理、依赖驱动调度、
   AudioAgent 去口癖、SemanticQAAgent 审片、视觉双层缓存、编码器试编码、
   感知按帧并行与场景自适应采样。
6. **本机环境满足约束**：Python 3.12.16、ffmpeg/ffprobe 7.1、pip 26.2.2、
   OpenCV 4.14、PySceneDetect 0.7.2、PySide6 6.12。
   默认测试 **232 collected（230 passed + 2 skipped live）**；真实 DeepSeek
   Planner 与 Orchestrator 全链路联调均 **已通过**。
7. **桌面形态已落地**：PySide6 单进程 GUI，直接调用 Services/Orchestrator，
   不启动 FastAPI；内嵌 ffmpeg/ffprobe、本地 whisper 模型、OpenCV Haar 数据，
   数据写 `%LOCALAPPDATA%\SmartCut`，API Key 存 Windows Credential Manager。
8. **主要风险不在架构，而在媒体语义、外部模型与打包**：`-c copy` 关键帧、
   concat 参数一致性、VFR/HDR/rotation、有理数取整、LLM 动态任务图合法性、
   场景/人脸检测准确率、PyInstaller 资源收集、ffmpeg 许可与包体。
9. **仍不是完整产品**：完整拖拽时间线/波形/缩略图轨、OTIO/FCPXML、
   SSE、平台预设、软字幕轨、多轨/转场/变速、鉴权与多素材尚未实现。

## 1. 需求分析

### 1.1 产品目标

把传统 NLE 中“复杂但可判定”的操作交给 AI，用户保留判断权与基础编辑能力：

- **AI 负责**：读转写/镜头/媒体事实，给出保留区间、顺序、标签、置信度。
- **系统负责**：Orchestrator 动态编排 → 编译 → 执行 → 校验 → 归档 → 可回放。
- **用户负责**：看时间线、改几个时间码、删/留 AI 建议、撤销、确认导出。

一句话：**AI 写时间线、Orchestrator 调度执行、ffmpeg 编译时间线、用户只审时间线。**

### 1.2 目标用户与场景

| 用户 | 典型素材 | 核心诉求 |
|---|---|---|
| 口播/知识博主 | 单机位、长口播 | 去口癖/长停顿、按主题切片、竖版导出 |
| 访谈/播客 | 多段对话、长时长 | 按话题粗剪、保留关键观点、生成字幕 |
| 课程/培训 | 屏幕+讲解 | 章节切分、去无效片段、平台合规导出 |
| 短视频运营 | 批量素材 | 批量粗剪、统一响度、9:16 重构图 |

共同点：**素材在本地、结果要可修改、判错要能回滚、源文件不能被破坏**。

P0/P0+ 的实现取舍：

- **转写可降级**：`faster-whisper` 未安装时返回 `degraded=true` 的空稿，
  接口不 500；安装后通过 `extract_audio → faster-whisper` 使用。
- **AI 规划可降级**：无 `DEEPSEEK_API_KEY` 时 `/plan` 返回 503；
  Orchestrator 自动只做分析/转写，或使用请求中的 `manual_ir`。
- **只做单素材、单轨、trim + concat**：先把契约与执行链打穿。
- **最终决策默认确定性**：保证可复现；可通过
  `SMARTCUT_LLM_DECISION_SUMMARY=true` 开启 LLM 自然语言总结。

P1 实现取舍：

- **9:16 为全局裁切**：在 concat 后按人脸/中心裁切到 1080x1920；
  逐段动态重构图留到后续。
- **字幕始终生成 SRT/VTT**，`burn_captions` 控制是否烧录；软字幕轨延后。
- **loudnorm 单遍**：目标 -14 LUFS，测试实测；两遍精确归一延后。
- **contact sheet 已生成并展示**，但尚未作为多图输入送给模型（需多模态接口）。
- **时间线**当前是片段条 + 镜头切点/质量标记 + 可编辑表格，不是完整拖拽 NLE。
- **OpenCV 锁定 4.x**：5.x 移除了内置 Haar cascade。

Phase 1/2 实现取舍：

- **候选片段是规划提示，不是硬约束**：Plan 仍校验章节范围与媒体边界；
  候选文本为空时（转写降级）按固定窗口生成。
- **FTS5 优先 trigram**：中文可做 3 字子串检索；短词/分词不匹配时用 LIKE 兜底，
  索引缺失时回退到按 score 排序的顶层候选，不阻断规划。
- **Critic 只做局部结构修正**：移除 black/blurry/duplicate 区间、按镜头/上限拆分
  长片段；必须提交新 revision，保留原 revision 可回滚。frozen 不视为坏帧。
- **Segment 缓存键不含输出路径**：同一裁剪参数跨 revision 复用；
  重复渲染时命中缓存直接复制，变化的片段才重新编码。
- **并行 cut 受资源池约束**：线程数取 `min(ffmpeg_concurrency, cut 数)`，
  主线程统一记录结果并按 seq 排序，避免并发写 DB/报告器。

### 1.4 用户必须保留的基础能力

1. 看时间线（片段、切点、文字稿/波形）。
2. 改任意片段的源区间。
3. 勾选/删除 AI 建议段。
4. 撤销/回滚到历史 revision。
5. 预览（P0 只提供数据接口，前端后续接入）。
6. 确认导出（dry-run 先看 ToolCall 计划）。

P0 已提供支撑：IR revision 版本表、dry-run、tool-call 审计、产物列表、
Orchestrator run 账本。前端时间线 UI 不在本次范围。

## 2. 技术方案评估

### 2.1 方案中最有价值的设计

1. **AI 输出 IR，而不是命令或成片**：非破坏性编辑、撤销、局部重渲、用户改时间码
   全部自然成立。
2. **三层职责清晰**：ffmpeg 管数据流、OpenCV/Whisper 管测量、模型管语义决策。
3. **Pydantic 作为单一事实源**：IR、JSON Schema、前端类型、工具参数可从同一模型派生。
4. **有理数时间**：避免浮点累计误差与 29.97/23.976 帧边界问题。
5. **Effects 严格不改时长**：堵住“变速混进 effect 导致时长漂移”的经典坑。
6. **Compiler 纯函数 + Runner 白名单**：AI 生成的代码/参数可被测试与安全边界拦住。
7. **Golden + 真实 ffprobe 断言**：不是“跑通就算”，而是“事实必须匹配”。
8. **Orchestrator 受控动态图**：比开放多智能体更可控，任务、依赖、失败语义都可审计。

### 2.2 文档内部张力与本项目取舍

| 文档表述 | 张力 | 本项目处理 |
|---|---|---|
| 感知层用 ffmpeg 抽帧/代理；同时规定 Runner 是唯一能起子进程的层 | 职责边界冲突 | 感知层只做纯解析；ffmpeg 调用全部走 Runner 工具（如 `extract_audio`） |
| Monorepo `packages/*` | 当前只有 Python 后端，多包收益低 | 采用 `src/smartcut/*` 单发行包，子包边界与文档分层一一对应 |
| `-c copy` 优先 | copy 只能落在关键帧，且 VFR/参数不一致会出问题 | P0 默认帧精确重编码；`copy` 保留为显式模式 |
| SSE 推送进度 | P0 前后端都未接 | P0 使用 REST 轮询；SSE 在接入前端时加 |
| SQLAlchemy + Alembic | P0 schema 尚小 | 使用 SQLAlchemy + `create_all`；表结构稳定后再引入 Alembic |
| Python 3.12/3.13 | 3.14 存在 OTIO binding 问题 | 锁定 `>=3.12,<3.14`，本机 3.12.16 |
| 模型名 `deepseek-flash` | 公开模型 ID 可能变化 | 通过环境变量配置，不硬编码 |
| 技术方案未提多智能体 | 用户新增 Orchestrator 要求 | 新增 `orchestrator/` 层，受控 DAG，不改变 IR/Compiler/Runner 铁律 |

### 2.3 技术栈兼容性

| 选型 | 评估 |
|---|---|
| Python 3.12 | ✅ 与 ffmpeg/OpenCV/faster-whisper/OTIO 兼容性最好 |
| FastAPI + Pydantic v2 | ✅ 已验证；请求/响应与 IR 共用模型 |
| SQLite + SQLAlchemy 2.x | ✅ 本地单用户足够；WAL + 短事务 |

### 3.3 核心契约

| 契约 | 关键字段 | 约束 |
|---|---|---|
| `RationalTime` | `value:int, rate:int` | rate>0；算术走 Fraction；只在 argv 边界转十进制 |
| `MediaFacts` | src、duration、fps、video/audio、vfr、rotation | ffprobe 的可序列化投影 |
| `Transcript` | words、segments、degraded | 词级/句级时间戳；缺失依赖时显式降级 |
| `EditIR` | schema、project_id、revision、media_facts、sequence、effects、audio、export | 单素材；effects 不改时长；project_id 安全字符 |
| `ToolCall` | seq、tool、args | 工具名限定；args 交由各工具 Pydantic 校验 |
| `OrchestratorTask` | id、agent、depends_on、max_retries、allow_failed_deps | 安全 id；agent 已注册；依赖存在且无环 |
| `AgentResult` | summary/output/artifacts/warnings/new_tasks/confidence | 子智能体标准返回；可动态扩展图 |

P0 明确拒绝：`effects` 非空、响度归一、BGM、字幕烧录、非 `mp4_h264` 预设、改帧率。
拒绝而不是静默忽略，避免“以为做了但其实没做”。

### 3.4 运行时流程

**手工/单智能体流程**

```
POST /projects/{id}/ingest 或 /upload
  → 源文件复制进 workspace/projects/{id}/media/
  → Runner.probe(ffprobe) → perception.parse_ffprobe → MediaFacts → SQLite

POST /projects/{id}/revisions        （手工 IR）
POST /projects/{id}/plan             （DeepSeek → EditIRDraft → EditIR）
  → 归一化 project_id / revision / media_facts
  → compiler.validate → Revision 入库

POST /projects/{id}/render {dry_run:true}
  → lower(IR) → ToolCall[] + 期望事实

POST /projects/{id}/render {dry_run:false}
  → 后台 Job：probe → cut×N → concat → verify
  → 成片 renders/r{revision}/output.mp4
```

**Orchestrator 流程**

```
POST /projects/{id}/orchestrate {goal, allow_render, manual_ir?}
  → 创建 OrchestrationRun（queued）
  → 后台 Job
  → TaskPlanner：LLM 生成任务图；失败/不可用则规则图
  → TaskGraphExecutor：
       analyze ∥ transcribe
              ↓
            plan
              ↓
          compile → render → verify
  → 智能体可返回 new_tasks 动态补齐后续阶段
  → DecisionAgent 汇总账本，输出 answer / confidence / warnings / artifacts
  → OrchestrationRun 更新为 succeeded / partial / failed
```

### 3.5 Orchestrator 设计（Magnetic-One 风格）

| 组件 | 职责 |
|---|---|
| `TaskPlanner` | 根据 goal + 项目状态构建 DAG；优先 DeepSeek 输出 `OrchestrationPlan`，非法则规则兜底 |
| `TaskGraphExecutor` | 依赖满足的节点并行执行；支持动态 `new_tasks`、重试、失败跳过、`allow_failed_deps`、环检测、最大轮次 |
| `AnalyzeAgent` | 读取 MediaFacts，标记 VFR/rotation/无音频等风险；可动态补充 transcribe |
| `TranscribeAgent` | 抽取音频 + 转写；缺依赖时降级；可动态补充 plan |
| `PlanAgent` | 调用 DeepSeek 或提交手工 IR，生成 revision |
| `CompileAgent` | 纯函数 lowering 为 ToolCall[]；可动态补充 render |
| `RenderAgent` | 执行白名单工具链，产出成片；可动态补充 verify |
| `VerifyAgent` | 再次 probe 成片，独立校验时长/音轨/分辨率 |
| `DecisionAgent` | 最终决策：汇总成功/失败/警告/产物，输出可读答案；可选 LLM 总结 |

关键语义：

- **动态图**：初始图可以只包含 analyze/transcribe/plan；PlanAgent 补 compile，
  CompileAgent 补 render，RenderAgent 补 verify。LLM 规划不完整时仍能跑通。
- **并行**：analyze 与 transcribe 无依赖，由线程池并行执行；测试用
  `threading.Barrier` 验证真正并发，而不是顺序执行。
- **失败隔离**：单个智能体失败可重试；失败后依赖节点标记 skipped；
  `allow_failed_deps` 允许汇总类任务继续。所有任务都记录 attempts/error。
- **最终决策**：即使部分任务失败，DecisionAgent 仍输出答案，说明成功数、
  失败任务、警告与可用产物。
- **可审计**：`OrchestrationRun` 保存 plan、ledger、answer、confidence、
  artifacts、warnings，便于回放与前端展示。

### 3.9 关键实现细节

**有理数时间**

- IR 只存 `{value, rate}`；总时长统一折算到 `rate=90000` 的时基。
- 帧精确换算用 `from_frames(frames, fps)`，29.97 时 `1 帧 = 1001/30000 s`。
- 只在生成 ffmpeg 参数时输出 9 位小数秒；校验比较用 `Fraction`。
- 不做隐式帧吸附；吸附是显式方法，留给需要的地方调用。

**Compiler**

- 输出顺序固定：`probe → cut×N → concat（>1 段）→ verify`。
- 路径相对项目工作区：`renders/r{revision}/...`，模型不接触路径。
- 单段直接写 `output.mp4`；多段写 `seg_000.mp4...` + `concat.txt` 再拼。
- 所有片段使用同一套编码参数（libx264 veryfast/crf18 + AAC 192k + timescale 90000），
  为 concat 流拷贝创造条件。

**Runner**

- `subprocess.Popen(argv, shell=False)`；二进制仅允许配置的 ffmpeg/ffprobe。
- `Workspace.resolve` 拒绝绝对路径、盘符、`..`、NUL、越界解析。
- `resolve_output` 拒绝覆盖输入；输出父目录自动创建。
- Windows 使用 `CREATE_NO_WINDOW`；UTF-8 + `errors=replace`；超时 kill。
- 每次执行写 JSONL 与数据库审计。

**Verify**

- 断言时长、fps、是否有音频、宽高。
- 容差 `max(tolerance_frames / fps, 0.1s)`，吸收 AAC priming 与帧边界差异。
- 期望时长由 IR 结构推导，不来自模型算术。
- Orchestrator 的 VerifyAgent 再做一次独立 probe 校验，作为第二道防线。

**本地转写（ASR）**

- `extract_audio` 统一输出 16k 单声道 PCM WAV。
- Transcriber 用标准库 `wave` + numpy 读成 float32 数组再传给 faster-whisper，
  绕开 PyAV 19 与 faster-whisper 1.2.1 的 `metadata_errors` 兼容问题。
- `numpy.float64` 时间值在 `RationalTime.from_seconds` 中先转 Python 标量。
- 打包后 `--self-check` 会用内嵌 ffmpeg 生成 0.5s WAV 并完成一次转写，
  验证 ctranslate2/onnxruntime/numpy 与模型文件都在包内。

**LLM 客户端 / Planner**

- DeepSeek OpenAI 兼容 `/chat/completions`，`response_format=json_object`。
- 本地 Pydantic 校验；非法 JSON/越界触发修复，Planner 最多 2 次，TaskPlanner 最多 1 次。
- 不可变事实（media_facts/project_id/revision）由系统填充，模型只给决策。
- 模型永不输出路径、命令或 shell。

**Jobs / 降级**

- 线程池执行，SQLite 原子状态迁移；前端轮询。
- 转写未安装依赖 → 空稿 `degraded=true`。
- 规划无 Key → 503；Orchestrator 只分析，或使用手工 IR。
- 渲染失败保留现场与错误信息，不自动篡改 IR。
- Orchestrator 即使部分失败也会产出最终答案与 ledger。

### 3.10 安全设计

| 面 | 措施 |
|---|---|
| 命令注入 | 参数化 argv、`shell=False`、禁止字符串命令 |
| 任意执行 | 工具白名单 + 二进制白名单 |
| 路径穿越 | 每项目 workspace 沙箱，拒绝绝对路径/盘符/`..`/NUL |
| 源文件保护 | 导入/上传只复制；后续只操作副本 |
| 覆盖素材 | 输入输出路径比对，禁止覆盖 |
| 资源滥用 | 每工具超时、并发线程上限、上传大小限制 |
| 模型越权 | 模型只输出 IR/任务图；本地严格校验；任务图环检测 |
| 供应链 | 重依赖 optional；桌面包内嵌 ffmpeg/whisper；仅 DeepSeek 走网络 |

### 3.14 Phase 2：候选检索、Critic 与渲染优化

**候选片段 + FTS5**

- `contracts/candidates.py`：`Candidate {id, source_range, text, score, tags,
  quality_flags, face_present, shot_boundary}`、`CandidateList`。
- `perception/candidates.py`：按转写句群成组（>5s 间隙 / 镜头切点 / 超长拆分），
  融合质量标记、人脸锚点、章节标题，生成可解释分数。
- `server/candidate_index.py`：SQLite FTS5 虚拟表
  `candidate_fts(candidate_id, project_id, source_hash, text, data_json)`；
  优先 `trigram` 分词（中文子串），失败回退 `unicode61`；
  查询词 = 拉丁词 + 中文 3 字 n-gram，MATCH 无结果时用 LIKE；
  索引按项目 + 源哈希隔离，重建候选时先删后插。
- Orchestrator 新增 `candidates` agent，依赖 frames/scenes/quality/faces/
  chapters/transcribe；Plan 前通过 `retrieve_candidates(goal)` 取 Top-N。
- Planner context 增加 candidates（时间、文本、score、tags、flags），
  提示词要求优先从候选区间选段，但不输出 candidate id/坐标/路径。

**CriticAgent 与局部重规划**

- `orchestrator/critic.py` 纯函数 `repair_sequence`：
  - black/blurry/duplicate 标记按 `t ± padding + 采样宽度` 形成禁入区间；
  - 从 trim 中扣除禁入区间，小于 0.5s 的残片丢弃；
  - 超过 `critic_max_segment_seconds` 的片段优先按镜头切点拆分；
  - 保留 tag/confidence，完全不修改 effects/audio/export。
- `CriticAgent` 依赖 plan；有修正时通过 `submit_revision` 创建新 revision，
  更新共享上下文后由 compile/render 使用；失败时保留原规划并告警。
- 任务图变为 `plan → critic → compile → render → verify`；
  无渲染时仍执行 critic，便于用户查看修正后的时间线。

**Segment 缓存与并行 cut**

- `ToolResult.cached` 标记命中；渲染结果返回 `cache_hits/cache_misses`。
- cut 缓存键 = `hash(source_hash, "segment_v1", CutArgs 去掉 dst)`；
  跨 revision 复用同一裁剪参数。
- cut 在线程池中并行，线程数 = `min(ffmpeg_concurrency, cut 数)`；
  ffmpeg 并发仍由 `ResourceManager` 二次限额。
- 主线程负责缓存复制/写库、Reporter 记录与按 seq 排序；worker 只执行工具。
- 非 cut 工具（concat/fit/subtitles/loudnorm/verify）保持串行，避免链式依赖错序。

**IR diff**

- `compiler/diff.py`：按 `(src, start, end)` 多重集合比较两个 EditIR，
  输出 added/removed/unchanged、计数、时长与 effects/audio/export 是否变化。
- `GET /api/projects/{id}/revisions/{rev}/diff/{base}` 直接返回结构 diff，
  不触发渲染，供桌面/自动化对比 revision。

**新增 API**

- `GET /api/projects/{id}/candidates`
- `GET /api/projects/{id}/candidates/search?q=&limit=`
- `GET /api/projects/{id}/revisions/{rev}/diff/{base}`

### 3.16 性能优化与 Agent 补全

**source_hash 持久化**

- `media_assets.source_hash` 在 ingest 时计算并写入；旧库通过 ALTER TABLE 补列。
- `_source_hash` 优先读 DB；重启/打开项目不再对长视频做全量 SHA256。
- 仍保留内容哈希作为缓存正确性的唯一依据。

**并行项目 bundle 与运行摘要**

- `DesktopController.open_project` 用线程池并行加载
  project/revisions/runs/artifacts/perception/proxy/outline。
- `list_orchestration_run_summaries` 不再解析 plan/ledger 大 JSON；
  完整账本通过 `GET /api/runs/{id}` 或双击运行记录按需加载。

**单次后处理**

- 新增 `postprocess` 工具：crop/scale + 字幕 + loudnorm 一次 ffmpeg 调用。
- 有视频 filter 时只编码一次；仅 loudnorm 时 `-c:v copy`。
- 旧 fit/subtitles/loudnorm 工具保留用于手工/兼容；
  Compiler 默认不再串联三次全片处理。
- 默认 libx264 argv 与旧 golden 保持一致；编码器 profile 注入方式不变。

**依赖驱动调度**

- `TaskGraphExecutor` 改为 ready queue + `FIRST_COMPLETED`。
- 任意节点完成立即调度新就绪节点，短分支不再等待长转写/长感知批次。
- 保留并行上限、重试、失败跳过、动态任务、取消和检查点回调。
- `max_rounds` 作为安全阀默认提高到 64。

**感知/视觉缓存前置**

- `get_perception` 按 source_hash + 各 artifact cache_key 做进程内缓存，
  避免 Plan/Candidate/Desktop 重复读取帧 manifest 与大 JSON。
- `build_visual_notes` 先用 source_hash + 章节 id + 图片路径查缓存；
  命中时不再打开/缩放图片。

**AudioAgent**

- 契约 `AudioSpec.remove_filler` 真正落地：按词级时间戳删除
  `um/uh/erm/嗯/呃/那个` 等口癖区间，提交新 revision。
- 不满足 0.4s 的残片丢弃；无词级转写时跳过并告警。
- 删除口癖后把 `remove_filler` 置 false，Compiler 不再告警。

**SemanticQAAgent**

- 在 Critic 之后审片，输入 EditIR/转写/感知/视觉 notes，
  输出 `EditReview {score, summary, issues[]}`。
- LLM 可用时调用 DeepSeek；失败或未配置时使用确定性规则审片。
- QA 不修改时间线；warning/error 进入最终答案，score 限制最终置信度。

**任务图**

```
plan → audio → critic → qa → compile → render → verify
```

**分块转写并行与静音筛选**

- `chunking.wav_rms` 对 16k mono PCM 计算归一化 RMS；块长 ≥0.5s 且低于
  `SMARTCUT_TRANSCRIBE_SILENCE_RMS`（0.002）时跳过模型，缓存空 Transcript。
- `SMARTCUT_TRANSCRIBE_WORKERS`（0=auto）：CPU 且 transcriber 提供 `clone()`
  时最多 2 个 worker；GPU/未知默认 1；仍受 `cpu_concurrency` 限制。
- `FasterWhisperTranscriber.clone()` 每次创建独立模型实例，避免共享
  CTranslate2 模型；无 clone 且未声明 `thread_safe` 时强制单 worker。
- 缓存读取/写入留在主线程，worker 只执行转写，避免 SQLite 并发写。
- 返回新增 `cache_misses`、`silent_chunks`、`transcribe_workers`；
  faster-whisper 内部 VAD 继续保留。

### 3.18 P1：视觉缓存、试编码与感知并行

**视觉摘要双层缓存**

- 整图缓存键：source_hash + 章节 id + keyframe/contact sheet 路径 + model +
  prompt_version + goal；命中时不打开/缩放任何图片。
- 单图缓存键：图片 sha256 + model/base_url/prompt_version + 章节 + goal。
- 整图未命中时，只把缺失图片批量发给 VLM，按 `image_index` 写回单图缓存；
  整图缓存删除但单图缓存仍有效时，不再调用 VLM。
- 最终 `VisualNotes` 由单图描述在本地按章节归并。

**硬件编码器试编码**

- `ffmpeg -encoders` 仅作为候选；每个硬件 codec 还需通过
  64x64、1 帧、`-f null -` 试编码。
- 失败 codec 从可用集合剔除，结果按 ffmpeg 路径 + size/mtime 缓存；
  避免第一次正式渲染才失败。

**感知并行与场景自适应采样**

- 质量分析将逐帧静态度量放入线程池；冻结/重复判断顺序串行，
  使用 160x90 灰度降低内存。
- 人脸检测按帧并行；Haar Cascade 使用 thread-local，避免共享 OpenCV 对象。
- 每帧任务单独获取 `cpu_slot`，总并发受 `SMARTCUT_CPU_CONCURRENCY`。
- `SMARTCUT_PERCEPTION_MAX_FRAMES`（默认 1200）限制分析帧数；
  优先保留镜头切点附近帧，其余均匀采样。
- 任务图调整为 `frames → scenes → {quality ∥ faces ∥ contactsheet}`；
  quality/faces 依赖 scenes，缓存键包含 scenes key 与 max_frames。

**契约与数据库**

- `AudioTrackSpec`：id、role、asset_id、素材区间、输出起点、增益、
  静音/独奏、淡入/淡出；`EditIR.audio.tracks` 为 `None/[]/非空` 三态。
- `AudioAssetRef`：编译期解析的音频资产（src/时长/声道/采样率/是否有音频）。
- 新增 `project_audio_assets` 表；导入音频复制到项目 `audio/` 并 probe；
  项目 bundle 返回 `audio_assets`，删除项目级联清理。
- API：`GET/POST /api/projects/{id}/audio-assets`、`POST .../separate`。

**混音编译器**

- `compiler/lower.py` 按 muted/solo 过滤轨道，解析 `AudioAssetRef`，
  生成一次 `mix_audio`：`atrim → asetpts → volume → afade → adelay`，
  多轨 `amix normalize=0`，再 `apad/atrim` 对齐成片时长。
- 主输出 volume/pitch/loudnorm 在混音后统一应用；无活动轨用 `anullsrc`。
- 需要 fit/字幕时先 `postprocess` 到 visual.mp4，再混音到最终 output；
  视频流始终 copy，只有音频重编码。
- 轨道超出成片时长时截断并记录 warning；引用无音频素材时跳过并 warning。
- BGM 循环：输入层 `-stream_loop -1`，`atrim` 铺满剩余时长，
  仍然只做一次音频编码。
- `mix_audio` 已加入 Runner 白名单与 `policies/tools.json`。

**音频面板**

- 保留主输出音量/音调；新增音轨表：素材下拉、导入音频、添加/删除、
  输出起点、每轨增益、静音/独奏、淡入/淡出。
- revision 载入时把 RationalTime 转为秒显示；编辑后写回 IR 并标记未保存。
- 新增音频资产导入与“分离人声/伴奏”；分离按钮在未安装 Demucs 时提示配置。
- 音轨表新增循环开关；时间线新增音频 lane，显示多轨块、静音/独奏/循环与
  按资产缓存的波形。
- 音频修改后 600ms 防抖生成低码率混音预览（`proxy/mix_<key>.mp4`），
  按轨道参数与资产哈希缓存；最终渲染仍保持单次音频编码。

**Demucs 适配器**

- `runner/separation.py` 定义 `Separator` 协议与 `DemucsSeparator` 实现；
  `build_separator()` 为后续 UVR/MDX 适配器提供工厂。
- Demucs 默认 2-stem（`--two-stems=vocals`），也支持 4-stem 参数；
  命令来源：`SMARTCUT_DEMUCS_COMMAND` → PATH → Python 模块。
- 打包形态为伴生 `SmartCut-Separator.exe`：内含 CUDA 12.6 PyTorch、
  Demucs 4.1 与内置 htdemucs，主程序只通过子进程调用。
- worker 写 `progress.json` 供主程序轮询；`auto` 设备优先 CUDA，
  不可用时回退 CPU。worker `--probe` 供 self-check 输出 torch/GPU 信息。
- 本机验证：torch 2.6.0+cu126、RTX 4060；伴生 worker 约 4.6GB，
  完整分发目录约 5.6GB。
- 不导入 torch；使用 `ResourceManager.cpu_slot`、超时与 CancellationToken。
- 输入抽取 44.1k 立体声 WAV；输出 vocals/no_vocals 映射为人声/伴奏；
  复制到 `cache/stems/<key>`，注册为项目音频资产。
- 缓存键 = `source_hash + demucs_v1 + model`；第二次调用命中缓存。
- 设置页与 `DesktopConfig` 支持 Demucs 命令/模型；`diagnostics` 输出可用性。

**测试**

  真实 ffmpeg 多轨渲染。
- `tests/test_audio_assets.py`：导入/列表/bundle/API、revision dry-run 混音、

### 4.4 结论与阶段建议

**结论：技术方案可行，P0 + Orchestrator + 桌面客户端 + P1 感知/包装 +
Phase 1 长视频执行闭环 + Phase 2 候选检索/Critic/渲染优化 +
Phase 3 大纲确认/硬件编码/代理优先/视觉摘要成立。**
当前架构把最大不确定性（媒体语义、模型输出、任务图合法性、长视频上下文、
打包资源）隔离在可测试、可降级、可取消、可审计的边界内；核心路径已用真实
ffmpeg、API 端到端、真实 DeepSeek 联调、OpenCV 感知、分块转写、章节化、
FTS5 候选检索、Critic 局部重规划、两阶段大纲、编码器回退、VLM 降级与
PyInstaller 构建验证。

阶段推进建议（按验收门槛，而非时间估算）：

1. **完整桌面时间线**：波形、缩略图轨、拖拽片段边缘、缩放/平移、
   播放头与预览同步；门槛：拖拽后 IR revision 正确、源文件不变。
2. **P2 增强**：平台预设断言、软字幕轨、两遍 loudnorm、contact sheet 多图理解、
   逐段 9:16 动态重构图。
3. **检索增强**：多模态候选（图像/音频特征）、跨素材检索、候选重排学习。
4. **P3 专业衔接**：OTIO/FCPXML 导出、多轨/转场/变速。门槛：
   `IR → OTIO → IR` round-trip 无损；FCPXML 不支持项如实报告。
5. **桌面产品化**：代码签名/安装器/自动更新、崩溃恢复、任务取消、
   完整时间线交互；在干净 Windows 机器上做多编码/长视频 smoke。
